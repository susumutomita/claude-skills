# AI くさい日本語を直す

出典は、Kiminori Yokoi（@nasuvitz）氏のスライド「AI臭い文章とは何なのか」（2026/9/28、豊洲会）である。スライドの主張と例を、この skill の運用の形に整理した。原文の転載ではない。詳細は原文を読むこと。

- https://speakerdeck.com/nasuvitz/ai-kusai-bunshou-toha-nanina-no-ka

## AI くさい文章とは

次の 3 つのどれかに当てはまる文章である。

1. 不要な対比、否定、留保から入り、主文を直接書かない。
2. 抽象語や比喩的な動詞を多用し、何をするのかが曖昧である。
3. 短文、対句、不自然な読点、名詞化で、内容以上に印象的に見せようとする。

読み手が困るのは、同じ癖に何度も出会うと、その人自身の判断や感性を感じ取れなくなるからである。後から文章だけを読んだとき、「誰が・何を・どうした」を復元できない文章は、書き直す。

## 検出の手がかり

| 手がかり | 例 | 何が足りないか |
|---|---|---|
| 指示語と抽象語で、対象を隠している | 「片方だけを見て基準を作ると、もう片方が壊れます」 | 「片方」「もう片方」が何か。「壊れる」とは何が起きるか |
| 判断を方向や位置の比喩で書く | 「判断に迷うものは、残さない側に倒します」 | 何を、どう扱うか |
| 短い否定のあとに、短い肯定を置く | 「依存構造は分割できない。動かしながら引き返す。」 | 動かす対象、引き返す条件、戻す状態 |
| 対句、または前後を入れ替えた反復 | 「読んで身に付けてから、効く。効いてから、身に付く。」 | 何を学び、どんな効果を得るのか |
| 主体の欠けた名詞化と、強調の読点 | 「前提を、経路が代わりに添える。」 | 「経路」が指すもの。処理する主体 |

## 直し方

1. 対象と、想定される問題を明記する。読み手に、指示語や比喩の解釈をさせない。
2. 行為の主体を書く。
3. 何をどうするかを、直接書く。
4. 否定から入る対比は、主文だけにする。対比が本当に必要なら、比べる 2 つを具体的に書く。
5. 強調のための読点を外す。

### 直した例

| 前 | 後 |
|---|---|
| 片方だけを見て基準を作ると、もう片方が壊れます。 | 開発速度だけを基準にすると、保守性の要件を満たせなくなるおそれがあります。 |
| 判断に迷うものは、残さない側に倒します。 | 採否を判断できない項目は、原則として除外します。 |
| 依存構造は分割できない。動かしながら引き返す。 | 依存関係を分離できないため、稼働中のシステムを変更し、問題が発生した場合は元の状態に戻します。 |
| 読んで身に付けてから、効く。効いてから、身に付く。 | 実際の業務で使い、効果を確かめながら使い方を習得します。 |
| 前提を、経路が代わりに添える。 | 運用者は問い合わせ先に応じた前提条件を参照します。 |

これらは出典のスライドの例である。

## 手順

### 書くとき

1. 書く前に、次の 3 つを決める。誰が読むか。何をしてほしい、または何を分かってほしいか。主文は何か。
2. 主文を先頭に置く。前置きや留保は、必要な場合だけ、主文のあとに置く。
3. 書き終えたら、「検出の手がかり」の 5 つを見直す。

### 推敲、レビューのとき

1. 各文に「誰が・何を・どうした」を当てはめる。答えられない文に印を付ける。
2. 印を付けた文ごとに、次の形で報告する。
   - 引用: 該当の文。
   - 型: 検出の手がかりのどれか。
   - 欠けているもの: 読み手が補う必要のあった情報。
   - 書き直し案。
3. 修正は最小にする。意味を変えず、文体を作者の口調に合わせる。

## 守ること

- **書き直しに必要な事実が原文にないときは、推測で埋めない。** 「片方」が何かを、文脈から確定できなければ、作者に聞く。
- 指摘は具体的にする。「AI くさい」と言うだけでは、直せない。引用、型、欠けているものの 3 点を必ず添える。
- 良い文まで直さない。すべての短文や対比が、AI くさいわけではない。直すのは、読み手が意味を復元できないものである。
- 作者の主張と判断は、変えない。表現だけを直す。

## スライドの場合

出典のスライドは、文章に加えて、AI が作るスライドの違和感にも触れている。3C や SWOT のようなフレームワークは、分析の構造を固定するが、図形の配置は作者が決め、局所的に使う。一方、AI が作るスライドは、説明の全体の流れが固定され、手直ししないと誰が作っても同じ流れになる。

スライドの原稿を書くときは、次を守る。

- 全体の流れは、作者が決める。AI の提案した構成を、そのまま使わない。
- 話者の説明がなくても、後から文章だけを読んで、「誰が・何を・どうした」を復元できるようにする。復元できないと、資料を再配布しにくい。

## 指摘を受ける側への説明

「AI くさい」という指摘は、それ自体が抽象的である。相手に伝えるときは、次の順で話すと通じやすい。

1. 「これはどういう意味ですか」と聞く。
2. 「こういう意味です」と返してもらう。
3. 「では、そう書きましょう」と、その言葉に置き換える。
